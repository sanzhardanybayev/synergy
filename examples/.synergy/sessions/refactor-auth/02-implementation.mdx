# Implementation Plan

Phases land sequentially; chunks inside each phase may run in parallel — see <CrossRef to="00-overview#sub-specs">sub-specs</CrossRef> and the orchestrator file.

<Phase number={1} title="Storage interface + dual write" status="proposed" estimate="2d" summary="Land the new TokenStore interface and dual-write to both stores.">
  - Define and freeze `TokenStore`.
  - Implement `ComplianceStore` against the new backend.
  - Wire dual-write in `TokenService.put`; reads still hit the legacy store.
  - Add structured logging at every store operation.
  - Verification: writes land in both stores for 100% of new sessions.
</Phase>

<Phase number={2} title="Cutover reads + migration" status="proposed" estimate="3d" summary="Swap read path; migrate legacy rows.">
  - Add a feature flag to flip reads to the compliance store.
  - Backfill job: stream legacy rows → compliance store, idempotent.
  - Canary read traffic (1% → 10% → 100%), watching p95 latency.
  - Stop dual-write once reads are at 100% for 24h.
  - Verification: zero divergence between stores during read-canary; backfill drops to zero new rows.
</Phase>

<Phase number={3} title="Cleanup + audit" status="proposed" estimate="1d" summary="Delete the legacy store, finalize audit trail.">
  - Remove dual-write paths.
  - Decommission `LegacyStore`.
  - Compliance audit packet: structured logs + design doc + migration receipts.
  - Verification: Riya signs off; legacy store deleted.
</Phase>
