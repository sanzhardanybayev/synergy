# Architecture

See <CrossRef to="00-overview">overview</CrossRef> for goals and constraints.

## Layering

The new design separates three concerns that the current middleware conflates:

- **Middleware** (HTTP boundary): unchanged public API — `authenticate(req)` and `requireRole(roles)`.
- **Token service** (logic): issuance, refresh, revocation. Pure functions over a storage interface.
- **Token store** (storage): the compliance-approved backend. Swappable; one implementation today, more later.

## Storage interface

The token store has a tight interface to make the swap safe:

```ts
interface TokenStore {
  get(id: string): Promise<TokenRow | null>;
  put(row: TokenRow): Promise<void>;
  revoke(id: string): Promise<void>;
  scan(opts: { since: Date }): AsyncIterable<TokenRow>;
}
```
